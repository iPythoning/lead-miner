# 信号源矩阵

> ⚠️ **本文档的外部 URL、供应商与接口形态均未在写作环境核实**（当时 WebSearch/WebFetch 不可用）。
> 落地前必须实地验证一遍，不要直接照抄路径。价格一律没写 —— 没核实过的数字不写进文档。

选源的唯一标准：**能证明这家公司"此刻正在为海外获客花钱或花力气"**。
静态的企业名录（黄页、工商全量）不是信号，那只是底库。

## 一、优先级矩阵

| 源 | 信号强度 | 获取难度 | 法律风险 | 结构化程度 | 建议顺序 |
|---|---|---|---|---|---|
| **Meta 广告库 API** | ★★★★★ | 低（官方公开 API） | 无 | 高（JSON） | **1** |
| 展会参展商名录 | ★★★★☆ | 低（公开页/PDF） | 无 | 中 | **2** |
| 地方商务厅组团公示 | ★★★★☆ | 最低（政府公示） | 无 | 中（常为 PDF/表格） | **2** |
| B2B 平台会员目录 | ★★★☆☆ | 中（分页/反爬） | 低（公开页） | 中 | 3 |
| Certificate Transparency | ★★★☆☆ | 低（crt.sh 公开） | 无 | 高 | 3 |
| 海关提单数据 | ★★★★★ | 需采购 | 无 | 高 | 4（要钱） |
| 招聘平台职位 | ★★★★☆ | 高（反爬狠） | **高** | 低 | 5（谨慎） |

## 二、逐源说明

### 1. Meta 广告库 API —— 最该先做的

**为什么第一**：这是唯一一个**免费、官方、公开、有结构化 API** 的强信号源。
在中国境内投放英文广告的公司 = 已经在为海外获客掏现金，付费意愿最强。
而且不用等任何人给你 CSV，今天就能跑。

**已实现**：`miner/collectors/meta_ads.py`。用法：

```bash
export META_ACCESS_TOKEN=...                    # 只从环境变量读，不进代码/日志/CSV
python3 -m miner meta-token-check               # ← 手上 token 到底能不能用
python3 -m miner meta-probe                     # ← 必须先跑
python3 -m miner meta-fetch --terms "hand tools" -o meta.csv
```

**`meta-token-check` 回答「我这个 token 是不是广告的」** —— 实际调用三次而不是翻文档：
`/me`（token 有效吗、是谁的）、`/me/permissions`（授了哪些 scope）、
`ads_archive`（**终极判据：能不能真读到广告库**）。

⚠️ 关键认知：**Ad Library 的门槛主要是「账号完成身份验证」，不是某个 `ads_*` 权限。**
所以 `ads_read`/`ads_management` 齐全也可能读不了；反之做完身份验证后，
一个普通 User Access Token 往往就够。别对着 scope 列表调半天 —— 以第三项实测为准。

**probe 不是可选步骤**。端点/字段/权限边界均未经核实，probe 用最小请求（limit=1）
打印真实响应结构与转换结果；失败时原样带出 Meta 的错误体 —— 那段话通常直接指出
是字段名不对、权限不足，还是该地区不可查。probe 没过就 fetch 只会拉回空数据或撞墙。

三个已知不确定性（probe 就是用来消解的）：

1. **非政治广告可见范围受限**：`ad_type=ALL` 在欧盟因 DSA 开放，其他地区可能只返回
   政治/社会议题广告。故默认按 `ad_reached_countries=DE,FR,IT,ES,NL` 查 ——
   中国外贸企业投海外广告，目标市场通常覆盖这些国家，能从这个口子捞到。
2. **返回里没有可靠的「广告主所在国」字段**：代码**刻意不做**「是不是中国公司」的强断言，
   而是把判断材料（页面名、落地页域名、语言、投放平台）原样带进 CSV 给人过一眼。
3. 字段名随 API 版本变化：`META_GRAPH_VERSION` / `META_AD_FIELDS` 可覆盖。

**产出是半成品，不是可入库线索**：广告库给得到公司名与落地页域名，**给不到电话**，
而 trade-crm 的 `Contact.phoneNumber` 必填且是唯一键。所以链路是：

```
meta-fetch → CSV（公司名+域名） → wigolo 抓这些域名的 contact 页补「电话/邮箱」两列
           → miner import --source meta-ads-<年月> --signal-date <广告开投日>
```

导出的 CSV 列名已对齐 `COLUMN_ALIASES`，补完两列即可直接 import。
一个广告主常同时投几十条广告，`dedupe_by_page` 按 page_id 收敛成一家一行，
并保留**最早**投放日（更接近「何时开始做海外投放」）。

### 2. 展会参展商名录

- **广交会官网参展商查询**（cantonfair.org.cn 系）：最全，按展区/产品分类，有分页
- **地方商务厅 / 贸促会组团公示**：完全公开、无反爬、常带公司名+主营产品+展位号。
  分散在各省站点，但胜在零阻力，适合起步
- **行业商会会员参展名单**：五金、家电、纺织等商会自己发，质量高、常带联系方式
- `--source canton-fair-<届数>` / `--source <展会名>-<年>`，`signal_date` = 开幕日
- 广交会参展商 100% 是出口企业 → 导入时直接 `--assume-import-export`

### 3. B2B 平台会员目录（新会员信号）

- 阿里国际站 supplier 页、中国制造网供应商目录、环球资源
- **拿"新会员"信号的低成本办法：每天抓一次 sitemap，diff 出新增 URL**。
  比逐页翻目录省几个数量级的请求，也不容易触发反爬
- 平台没有对第三方开放会员 API，只能走公开页
- `--source alibaba-new-<年月>` / `--source mic-new-<年月>`

### 4. Certificate Transparency 日志（新站上线信号）

- crt.sh 等 CT 日志是公开的：**新签 SSL 证书 = 新域名上线**
- 过滤新注册的英文外贸独立站（配合 WHOIS 注册地=CN）
- 信号含义：这家公司刚搭好海外站，正要开始推广
- `--source ct-newsite-<年月>`

### 5. 海关提单数据（要采购，但一鱼两吃）

**唯一同时解决两个问题的源**：一条中国出口提单，左边是中国供应商（我们的线索），
右边是海外采购商（我们卖给客户的交付物）。

- 国内商：腾道 TendData、易之家 —— 中国出口侧
- 海外商：Panjiva（S&P Global）、ImportGenius、Volza、ImportYeti —— 进口国侧
- ImportYeti 主打美国进口提单，起步成本低，适合先验证「买家线索」这个卖点
- 自带资格审查：能出现在提单里的公司，确定在做出口、有实单

### 6. 招聘平台（放最后，且只取公开职位）

- 信号强（招外贸业务员 = 正在扩海外团队），但**法律风险最高**
- **只取「公司名 + 职位名 + 城市 + 发布时间」**，绝不碰简历库、绝不碰候选人个人信息
- 抓简历 = 刑事风险（参见 2019 年简历数据行业案例），与抓公开职位差一个数量级
- 反爬也最狠，投入产出比不如前五个

## 三、工商补全 API 供应商

补全只为两件事：统一社会信用代码（跨源去重的稳定身份）、经营范围有无进出口权。

- 企查查开放平台 / 天眼查开放平台 / 爱企查（百度）—— **当前选型：爱企查**
- 接入方式见 `enrich.py`：端点、鉴权、字段映射全部 env 注入，代码里不写死 provider

## 四、合规红线（所有源通用）

1. **只用企业公示联系方式**：工商公示电话、官网 info@/sales@、名录登记电话。
   个人手机号、个人邮箱、简历数据一律不碰 —— PIPL 下无合法性基础。
2. **遵守 robots 与频率**：公开不等于可以高频抓。低频、分散、带 UA。
3. **给客户交付欧盟买家线索时**必须带 opt-out（GDPR 正当利益路径的前提）。
4. 平台会员页属公开信息，但**批量抓取仍可能违反平台 ToS** —— 商业风险自担，
   与刑事风险不是一回事，别混为一谈。

## 五、接入约定

不管哪个源，wigolo 抓完导出 CSV（列名中英文常见写法都认，见 `records.py` 的
`COLUMN_ALIASES`），然后：

```bash
python3 -m miner import <名录>.csv --source <源标识> --signal-date <YYYY-MM-DD> [--assume-import-export] --dry-run
```

`--source` 命名保持稳定：它是幂等键前缀，也是 trade-crm 里的 tag。
同一家公司被多个源命中会各记一条，这是**故意的** —— 多源命中本身就是强信号。
